# 08 验证视角

## master agent 要能产生什么？

Master agent 至少要能产生：

- single read / single write
- `FIXED / INCR / WRAP` burst
- 不同 `AxLEN / AxSIZE / AxBURST`
- backpressure 场景
- outstanding transaction
- 不同 ID
- narrow transfer
- unaligned access
- error response 触发访问

## slave agent / memory model 要能做什么？

Slave agent / memory model 至少要能：

- 接收 `AW/AR`
- 根据 `W` beat 和 `WSTRB` 更新 byte-addressed memory
- 根据 `AR` 返回 `RDATA/RRESP/RLAST`
- 插入随机 latency 和 backpressure
- 注入 `OKAY/SLVERR/DECERR`

## monitor 要还原什么？

Monitor 不能只看一个通道。它要从 pin-level 信号恢复 transaction：

- 从 `AWVALID/AWREADY` 采集写地址事务。
- 从 `WVALID/WREADY` 采集每个写数据 beat。
- 用 `WLAST` 判断写 burst 结束。
- 从 `BVALID/BREADY` 采集写响应。
- 从 `ARVALID/ARREADY` 采集读地址事务。
- 从 `RVALID/RREADY` 采集每个读数据 beat。
- 用 `RLAST` 判断读 burst 结束。

## scoreboard 最关键

Scoreboard 的核心不是“比较一下读写结果”，而是维护一个 byte-addressed reference memory。

写事务：

```text
expected_mem[address + byte_offset] =
    WSTRB[byte_lane] ? WDATA[byte_lane] : old_value
```

读事务：

```text
actual RDATA 应该等于 expected_mem 中对应 byte lane 的内容
```

narrow / unaligned / WSTRB 是 scoreboard 最容易写错的地方。

## assertion 应该抓什么？

最基本的 assertion：

- `VALID && !READY` 时 payload stable。
- `WLAST` 必须出现在第 `AWLEN+1` 个 W beat。
- `RLAST` 必须出现在第 `ARLEN+1` 个 R beat。
- `BVALID` 不能早于写地址握手和最后写数据 beat。
- burst 不能跨 4KB boundary。
- `BID` 必须匹配 outstanding `AWID`。
- `RID` 必须匹配 outstanding `ARID`。
- 同 ID response ordering 不能破坏。

## coverage 应该覆盖什么？

功能覆盖点：

- channel：`AW/W/B/AR/R` 是否都经历 backpressure。
- burst type：`FIXED / INCR / WRAP`。
- burst length：`AxLEN=0`、中间值、最大值。
- transfer size：不同 `AxSIZE`。
- response：`OKAY / EXOKAY / SLVERR / DECERR`。
- ID：single ID / multiple ID / same ID ordering / different ID out-of-order。
- data：full-width / narrow / unaligned / partial `WSTRB`。
- boundary：接近 4KB 边界、不跨界、非法跨界。

## 验证环境是否有效？

不要只看 golden DUT 全部 pass。还要做 bug injection：

- READY=0 时改 payload。
- WLAST 提前或延后。
- BVALID 提前返回。
- 忽略 WSTRB。
- narrow/unaligned 地址映射错。
- 同 ID 响应乱序。
- 返回错误的 BID/RID。

如果这些故障版本能被 assertion / scoreboard 抓到，验证环境才有可信度。
